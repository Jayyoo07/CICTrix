How should Supabase tables look while they load?

Each table below replays a load. Pick a latency to feel the difference between a fast and a slow connection. Today the page shows nothing, then the rows pop in.

ASkeleton rows (shimmer)

Gray placeholder bars shaped like the real columns, with a soft sweep. The table header, toolbar and footer render immediately; only the body is a placeholder. The layout doesn't jump when data arrives.

CA skeleton on first load, then a progress bar on refresh

First visit: skeleton rows as in A. Later refetches (search, sort, next page, after saving) keep the old rows visible but dimmed, with a thin indeterminate bar under the header, so the table never blanks out. Click "Refetch" after the first load.

Used by: Vercel, Linear, Notion databases, TanStack Query's "keep previous data" pattern.

Timing rules that apply to whichever you pick

  • Wait about 200ms before showing the loader. Fast loads go straight to data with no flash of skeleton (try the 250ms setting).
  • Once shown, keep it at least about 400ms, so it doesn't blink on and off.
  • Show the same number of placeholder rows as the page size (5 or 8 here), so the table keeps its height.
  • Fade the real rows in over 200ms, and turn animation off under reduced motion.
  • Mark the table as loading for screen readers with aria-busy="true" and a hidden "Loading…" status.
  • If the fetch fails, show the error in the table body with a Retry button, never an empty table.
